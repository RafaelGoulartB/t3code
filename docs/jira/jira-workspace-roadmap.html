Definition of done

Acceptance criteria

Reliable

A successful comment becomes confirmed from Jira or clearly says it needs verification. A failed write preserves user text.

Predictable

Every list group corresponds to a returned sprint or the explicit outside bucket. No mass item-detail loading.

Secure

Only argument-array ACLI calls; no REST credentials, raw stderr or CLI auth output in the product.

Risks & mitigations

Keep the integration dependable

Risk Mitigation
ACLI eventual consistency after comment creation Short bounded refetch sequence and an honest “Sent to Jira — refresh to verify” state.
Different Jira workflows and field support Server-side normalization; dialogs preserve previous UI state and display only safe error categories.
Many accessible boards and sprints Short-lived cache, limited batches and visible total caps; refine by project or sprint.
Existing coding draft Require a deliberate choice before opening/replacing a draft; never overwrite silently.
